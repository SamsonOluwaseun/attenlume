## Report and controls

- `docs/reports/OVERNIGHT_LATEST.md`: continuously updated morning report.
- Session `MORNING_REPORT.md` and `state.json`: task state, PID, active command,
  checks, base/candidate commits, peer outcomes and platform limitations.
- Per-command stdout/stderr logs, full agent responses, binary diffs and local
  docs before/after each candidate are in the session log folder.
- `tool/logs/supervisor.log`: append-only human timeline across sessions.
- Create `STOP` in the session folder to stop the active command tree and refuse
  new work. Incomplete work stays in its isolated branch; no automatic reset.
- A deadline-aware timeout kills only the command tree launched by this runner.
  A maximum run count, dependency gates and exclusive lock prevent runaway loops
  and duplicate instances. A crashed process can leave a stale lock: check its
  PID before manually removing it; never delete a live runner's lock.
- The system stays awake during the runner and the wake request is released on
  completion. Closing/suspending the machine or terminating its process can still
  interrupt work. No boot/logon task or system configuration is installed.

Each merge runs locked pub get, analyze, format, tests, licence audit, sync and
supervisor tests, Android debug build and Windows debug build, followed by a
read-only peer review and a clean-tree/unchanged-commit check. Mac source exports
follow integration. iOS compilation and physical-device acceptance still need
the Mac and relevant hardware; never infer their success from Windows checks.

Completed task reports list changed files and actual validation evidence. Screen
changes must refresh guide text and report any screenshots/doc artefacts that
could not be regenerated. Tasks must not fake recording/device evidence.
