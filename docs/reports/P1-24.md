# P1-24 report: Privacy UX and optional app lock (FR-PRI-01 to 06)

Builder: Claude Code (Opus 5.5), 28 October 2026. Branch `phase-1/P1-24-privacy`, based on main `a4ec681`. Decision record: ADR-041.

## What was built

| Requirement | What exists now |
|---|---|
| FR-PRI-01 | `checkRecordingPrivacy` runs before every start from the recording screen: the recording policy reminder once per conference if it was never acknowledged (saved with `acknowledgePolicy`), and the FR-ACT-07 awareness check for conversation and networking activities whose answer is still `unknown`. "Not now" holds the start back; "Not recording audio" is saved and the start is refused with the existing message. |
| FR-PRI-02 | `RecordingBanner` (Recording, Paused, Interrupted and so on, with Open and Stop) above the conference list and conference home while a recording is held. The app lock cover also shows "Recording is still on" with Stop. No setting hides either. |
| FR-PRI-03 | Privacy screen (from the new menu on My conferences) states the on-device promises. Tests fail if a known analytics, advert or tracking package enters `pubspec.lock`, or if the Android main manifest asks for `INTERNET`. |
| FR-PRI-04 | Privacy screen lists every permission with when it is asked and why (wording from PRIVACY_AND_SAFETY 6), plus the Face ID / biometrics prompt for app lock. `NSFaceIDUsageDescription` added. |
| FR-PRI-05 | `SensitiveExportWarning.show(context, isUpload:)` dialog: identifiable people, unpublished research, commercial, medical or financial content, and a note that the app does not replace the user's legal obligations (UK GDPR). Never says "compliant". **Not wired into an export flow**: P1-21 is building export in parallel and should call it before starting. |
| FR-PRI-06 | Optional app lock via `local_auth` 3.0.2 behind `DeviceAuthenticator` (`lib/platform/device_auth/`), with `AppLockController` and `AppLockGate` (in `MaterialApp.builder`). Off by default; turning on needs one successful prompt; locks on start and after the grace period in the background (Immediately, 1 minute default, 5 minutes); fail-safe "Turn off app lock" when the device can no longer check. Never stops or pauses recording. |

## Open questions

1. Grace period: the guide gives none. I chose 1 minute by default so system pickers and the share sheet do not re-lock the app mid-task. Owner may prefer Immediately.
2. Should the lock also apply while a recording is running? I chose yes (the cover shows Stop and "Recording is still on", without the title). An alternative is to skip locking while recording.
3. Starts from notifications or shortcuts cannot show the FR-PRI-01 reminder (no UI). The recorder still refuses "not recording audio" activities.
4. The notification Photo action opens the camera under the cover until the person unlocks.

## For the reviewer

- `AppLockGate` keeps the routes mounted under the cover (`ExcludeSemantics` and `ExcludeFocus`), so the recording screen keeps its state. Check this is acceptable; it also means the Ctrl+B hotkey on Windows does nothing while locked.
- Error mapping in `LocalAuthDeviceAuthenticator.resultForCode`: `deviceError`, `unknownError`, `uiUnavailable` and `biometricHardwareTemporarilyUnavailable` count as "unavailable" and so allow "Turn off app lock". This is the fail-safe direction the Lead asked for; it is a trade-off against strictness.
- `MainActivity` now extends `FlutterFragmentActivity`. The four channel attachments, `onNewIntent`, `onResume`/`onPause` counters and `cleanUpFlutterEngine` are unchanged; a test checks the channels are still attached.
- P1-21 (export) needs to call `SensitiveExportWarning.show` before an export starts. P1-25 (Settings) should link to `PrivacyScreen` rather than repeat it.
- Process note: an early run of the gate test hung because the recorder's status stream was closed in `tearDown` inside fake async. The tests now dispose the recorder inside each test (same pattern as `recording_screen_test`). The orphaned `flutter_tester` from that run held `build/native_assets/windows/sqlite3.dll` for several minutes, then exited by itself.
